The GPU module is the gpu module of warp_core, re-exported by warp_sdk, which holds the formats, buffers, post-processing chain and readback tools of the engine. A game uses a small part of it: the target formats for its own passes, try_build for optional GPU objects, and the headless hash in gpu::pixhash. Most of the rest is engine plumbing that the module makes public, and several submodules serve editor panels.

The module is plain wgpu. warp_sdk re-exports the wgpu crate, and Renderer::scene_underlay and Renderer::scene_overlay hand a game the encoder and the targets. Post effects gives post effects with one switch each, and Render passes covers draw order.

Formats and the HDR chain

Main article: Post effects

The scene renders to an HDR target, and the chain then produces the LDR image.[1]

Constant Value Meaning
HDR_FORMAT Rgba16Float The HDR scene target. All scene pipelines target this format, not the surface format.
Z_FORMAT R16Float The linear depth channel, written beside HDR.
MSAA_SAMPLES 1 Sample count of every scene pipeline.
BLOOM_MIP_COUNT 5 Bloom blur levels.
BLOOM_MIN_INTENSITY 0.001 Below this intensity the bloom passes do not run.

MSAA_SAMPLES was four, and FXAA replaced it after tonemapping. The name stays because the pipeline definitions read it and a multisample state still needs a count.[2]

PostProcessParams is the uniform block of the chain. Its fields and defaults are:

Field Default
bloom_threshold 0.0
bloom_intensity 0.25
bloom_radius 1.2
exposure 1.0
saturation 1.5
contrast 0.994
temperature 0.0
brightness 0.0
shadows_tint [1.0, 1.0, 1.0, 0.0]
highlights_tint [1.0, 1.0, 1.0, 0.0]

PostProcessParams::apply_display copies the pp_* fields of DisplaySettings into the block. The frame and the Android host both call it, so the two cannot disagree about what a switch does. With pp_bloom_enabled false it sends an intensity of exactly zero, so stale bloom mips give nothing to the picture. With pp_grade_enabled false it sends the identity grade, because the tonemap shader has no grade flag.[3]

PostProcessChain owns the textures, pipelines and bind groups of the chain and is recreated on resize. FxaaPass, DofPass, ZDofPass and MotionBlurPass are the separate passes. ZDofPass reads the tonemapped colour and the Z_FORMAT channel. Objects at the focal depth stay sharp, and other objects receive a Poisson disc blur in proportion to their distance from it. MotionBlurPass reprojects with the delta between the previous and current camera, and it needs no depth or velocity target.

CrtPostProcess and CrtParams are the CRT filter. The filter holds separate targets for the scene and for egui, and composites them at the end.[4] barrel and tube_parallax are CPU copies of two WGSL functions. They exist so that a test can check the geometry with no GPU, and the source warns against removing them as dead code.[5]

Optional objects: try_build

try_build runs a closure inside a wgpu Validation error scope and returns nothing if an error was recorded. wgpu 0.16 sends a validation error with no open scope to an uncaptured handler that panics by default, so a shader that the DX12 back end cannot compile is a crash of the whole process, even for an effect that the user can turn off.[6]

On failure, the value is dropped and one line goes to stderr and to the boot log. gpu::guard::describe gives the error text. The caller disables the object.

The scope has three limits:

  • On wasm32 the future is a JavaScript promise that block_on cannot finish, so the web build runs the closure with no scope.
  • Error scopes form one stack per device, not per thread. try_build is unsafe to call while another thread can push or pop a scope on the same device.[7]
  • The function does not call device.poll, because a poll waits for queued GPU work and stalls boot.

Device and buffers

create_device_and_surface and create_surface_for_window build the wgpu objects, and GpuContext holds the instance, surface, device, queue and surface configuration. On native targets the device first requests raised limits, and then the wgpu defaults if the driver refuses them. Only the storage binding size and the buffer size change, and they never go below the defaults. The value WARP_GPU_LIMITS=default opts out.[8]

choose_present_mode picks a present mode from the surface capabilities. set_uncapped is called with true only when window.frame_cap_hz in the App manifest is above 60, because Metal offers Fifo and Immediate but never Mailbox, and Immediate tears, so an application must ask for it.[9] At run time, Display mode is the path for these choices.

DynamicBuffer is a GPU buffer that grows when the data exceeds its capacity. Growth is by powers of two, held at the device limit. Old buffers stay alive for two frames so that the GPU can finish reading them.[10]

Pipelines holds the render pipelines of the engine. RectTargetMode, LineTargetMode and CircleTargetMode choose scene or surface pipelines. ViewUniform holds the view uniform buffer and bind group. VIEW_PRELUDE is the text of view.wgsl, which goes in front of each scene shader. A registered layer gets the same string at run time, so its shader must not declare struct View again. See Render passes.

Headless proof: pixhash

gpu::pixhash is the visual baseline tool of the engine. It opens a device with no window, renders to an offscreen target, reads the target back and reduces the pixels to one u64. Two renders of one scene give one number, and a changed number names a changed picture.[11]

Function Purpose
headless A device and queue with no surface, or None where no adapter answers
offscreen A target that a pass can draw into and a copy can read
read_rgba Copy a target back and normalise BGRA to RGBA
hash_rgba The stable reducer
hash_texture Read back and reduce in one call

CAPTURE_FORMAT is Rgba8Unorm, which reads back with no channel swap on every backend. The module does not choose a golden value. A gradient rasterised on two backends can round two ways, so a committed golden value is per host. The Boot splash and screenshots kit uses headless and offscreen in its tests.

Load events

LoadEvent is the progress queue for asset loading. The background loader and the scene texture loader of the application call push_load_event, and the host application calls drain_load_events each frame. Nothing in warp_core drains the queue: the host reads the events and draws its own loading screen.

The queue holds LOAD_EVENT_LIMIT events, 512, because one mega-atlas pushes one event per texture layer. When full, it drops the oldest progress event. The AllTexturesComplete and LoaderFailed events are never dropped, because a host that loses either one waits on the loading screen for ever.[12] load_events_dropped counts the loss.

Probe

gpu::probe gives each frame layer its own clear colour. A hole in a frame is otherwise black, and every layer clears to black, so a black area names no pass.[13]

Colour Constant Reading
Magenta SURFACE The window blit did not reach this area.
Blue LDR The post chain did not write this area.
Green HDR The chain wrote it, and nothing was drawn here.
Black A pass wrote black on purpose.

The probe is off unless the WARP_PROBE environment variable is set, so a shipped build pays one atomic load per frame.

WARP_PROBE=1 ./game

The game view

GameView holds the finished game image as a texture that an egui panel can draw. The normal frame draws egui into the LDR image and blits both to the surface. Embedded mode inverts this: the CRT pass writes to this texture, the GUI pass targets the surface, and a panel samples the texture. Only the destination of two passes changes, so the image in the panel is the game image.[14]

GameView::ensure builds the texture in the primary viewport, and GameView::register_in gives one window a texture id for it. The split is what lets the Game panel tear off into its own window, because an egui::TextureId means nothing to another renderer but all windows share one device. A window can hold a second, nearest-filtered name through GameView::register_nearest_in.

GameView::adopt puts an imported surface from another process in the same slot, which is how a hosted game reaches the panel. An adopted slot must not be rebuilt or drawn into.

GameViewAspect is the shape that the game is asked to render at. fit_centered fits an aspect in a panel rect, rounded to whole pixels, because a half-pixel origin makes the linear filter blur a still image.

Editor readback

gpu::capture brings one whole frame back to the CPU on request. A panel draws inside the egui run closure and holds no device, and the render loop does not know which screen a picture is for, so the module is a flag, a readback and a slot. capture::request asks, capture::serve runs once a frame from the loop, and capture::take collects. capture::IDLE, capture::MANUAL, capture::AUTO and capture::GAME tag the asker, so a frame stays with the asker that wanted it. The stall on the render thread is deliberate and bounded, because a capture happens only a few times in a session.[15] capture::abandon also drops a served frame that nobody collected.

gpu::peek reads a small rectangle every frame with no stall. peek::MAX_EDGE is 256 pixels, and three staging buffers, allocated once, cost 768 KiB in all.[16] peek::serve polls and never waits, so the numbers may lag the picture by a frame or two. When two results complete at once, only the newest survives. The result is a Peeked value, with the rectangle actually read in Region.

Debug buffers

gpu::debugbuf holds the table of debug channels. A debug buffer is the scene shaded to report one property of each fragment. debugbuf::MODES has 19 entries, and debugbuf::SECTIONS groups them for the panel. A channel is a question that not every primitive can answer, because the engine has no g-buffer. A primitive that cannot answer paints its kind colour at 10 percent, not black, which separates an object with no normal map from an object whose normal points away.[17]

A debug mode skips bloom, tonemap, depth of field, FXAA and CRT, because those are correct for a picture and wrong for a measurement. DebugBlit copies the HDR target directly to the LDR image. A dump renders each channel again inside one frame, so all channels show the same camera at the same instant, and debugbuf::write_dump lays the set out as a sheet.

Editor renderers

These modules share one mailbox shape: a process global that holds the wgpu resources, a global that the panel writes each frame it is visible, and a texture global that the panel reads. The primary viewport creates and registers the resources before the GUI closure and draws after it, so the picture is from the current frame.[18] Because the primary viewport issues the texture id, the Shader, Office, Cornell and Splats panels are not tearable.

  • PlanetPreview renders the selected planet with the world circle pipeline into a square of PREVIEW_SIZE, 768 pixels, and tonemaps it with the same ACES curve. The other modules follow its shape.
  • ShaderLab compiles one WGSL file from the Shader panel and draws a fullscreen triangle. Every build runs in an error scope, because the file may be half edited. LabStatus reports the result.
  • Office is a forward renderer of low-poly meshes for the Sauron Office panel, with a depth buffer, one directional sun, warm ambient and distance haze. Its shadow map is 4096 pixels square.[19]
  • Cornell is a path tracer that adds samples to a running average held in float targets, then tonemaps into a texture for egui.
  • Splat draws a cloud of 3D gaussians as instanced quads. Draw order comes from a CPU back-to-front sort that runs one frame behind, because alpha blending is not commutative and a depth buffer keeps one fragment and rejects the others.[20]

Limitations

The engine scene has no depth test, as Render passes describes. Office is the exception inside this module, and it creates and binds its own depth target.

Only the primary viewport can fill the offscreen targets. See the Host link article for the case where the game runs in another process.

#pub fn tube_parallax(p: [f32; 2], q: &CrtParams) -> [f32; 2]

How far the mask slides against the phosphors at this point on the tube.

The two planes are at fixed depths behind the glass, so this is closed form: refract the eye ray at the faceplate, march it to the mask plane and to the phosphor plane, and return the difference of the two hits. No scene depth is involved and none could be — the depths are constants of the tube, not of the picture.

The difference is what is returned, and that is the whole reason this is usable as a post-process. Each absolute hit carries a magnification from looking through thick glass, which does not vanish at zero curvature; the magnification is common to both and cancels here.

#pub fn choose_present_mode(caps: &wgpu::SurfaceCapabilities) -> wgpu::PresentMode

Choose the best present mode for the current surface.

Prefers Mailbox (triple-buffered, non-blocking) which eliminates vsync stall cascading on DX12. Falls back to AutoVsync (Fifo on most Windows drivers) if Mailbox is unsupported.

IMMEDIATE, AND WHY IT COMES FIRST WHEN IT COMES AT ALL

Metal advertises [Fifo, Immediate] and never Mailbox, so on macOS this function could only ever reach Fifo — a hard vsync lock, whatever the frame cap said. Immediate was present on the surface the whole time and unreachable. It is tested first, and only for an application that declared an above-60 cap, because a game that wants 240 frames wants the present call not to block and has accepted the tearing that buys.

#pub fn ensure( device: &wgpu::Device, format: wgpu::TextureFormat, width: u32, height: u32, )

Create the game view once. Later calls with the same size do nothing, so this is safe to call every frame.

A size change rebuilds the texture and bumps the generation, which invalidates every window's registration. A window resize changes the render size, so the rebuild path runs whenever the user drags a window edge.

The old TextureIds are NOT freed here, and cannot be: an id belongs to the renderer that issued it, and this call has no window in its hand. Each window frees its own in register_in, which is also what guarantees nothing samples a stale one — every window re-registers at the top of its own frame, before it draws. A FOREIGN image is kept whatever the size, and that case is the reason this function has an early return that is not about cost. An adopted surface is the panel's size and this is called with the window's, so the size test never matches and every frame would have rebuilt over the game — the editor throwing away the link one frame after making it, and then showing its own empty scene in the panel as though no game had launched at all.

#pub fn adopt(tex: wgpu::Texture, format: wgpu::TextureFormat, width: u32, height: u32)

Take a texture somebody else owns as the game image.

The texture is a GAME'S, imported from the IOSurface it renders into in another process. Everything downstream of here — register_in, the panel's fit, the published rect, the pointer routing — cannot tell the difference and must not be able to, which is the whole reason this is a GameView and not a second path beside one.

WHY IT IS NOT ensure

ensure CREATES, and its no-op case is "same size, same format". Both are wrong here. The texture arrives made, so there is nothing to create; and a new surface at the SAME size is still a different texture, so a size comparison would keep the old one and leave the panel sampling a surface the game has stopped drawing into.

So the caller decides when this runs — on a Surface message and at no other time — and every call rebuilds and bumps the generation, which re-registers the id in every window on its own next frame.

#pub fn register_in( device: &wgpu::Device, gui: &mut egui_wgpu::Renderer, vp: crate::types::ViewportId, )

Give one window's egui a name for the game image.

THIS is what makes the Game panel a panel like any other. A TextureId is an index into the renderer that issued it, so the one id the primary window held was the reason the panel could not be drawn anywhere else. The texture itself was never the obstacle: every window in this process shares one wgpu::Device, so the same TextureView registers in as many renderers as ask for it.

Call it once per window per frame, before that window's GUI closure. It returns immediately after the first, and the ordering is what keeps a rebuild safe: by the time a window draws, it has re-registered.

Registering is a bind group, not a copy — so the cost of a second window showing the game is a bind group, once.

#pub fn register_nearest_in( device: &wgpu::Device, gui: &mut egui_wgpu::Renderer, vp: crate::types::ViewportId, )

The SAME texture, named again with a NEAREST filter.

The linear id above is right for the Game panel and wrong for a MAGNIFIED draw. The CRT pass writes discrete phosphor cells into this texture, and a linear sampler averages neighbouring cells the moment a draw asks for less than one texel per output pixel — which is what a preview box magnifying a patch of the screen does. The cells arrive as a grey wash, and the person tuning them sees nothing to tune.

Two ids over one TextureView cost one bind group. Nothing is copied and no pass is added: the picture in the box is the finished frame the window is already showing.

EVERY GUARD HERE IS LOAD-BEARING

register_native_texture MINTS an id and inserts it. It never replaces one, and the renderer frees nothing it was not asked to — so calling this per frame without the generation test orphans a bind group per frame, each one holding the whole render target alive.

Call it once per window per frame, beside register_in and before that window's GUI closure. The order is what lets the panel find its own id: this marks the window, and the panel reads the mark.

#pub fn forget_window(vp: crate::types::ViewportId)

#pub fn request(key: u64, region: Region)

Ask for region, as key. Call every frame while a panel wants a stream. The last asker before serve runs is the one served.

A request is TAKEN by serve and not kept. A panel that stops calling this stops the copies with it, so a panel that closes without calling abandon still costs nothing after its last frame.

One short mutex hold, and no GPU work on this thread.

#pub fn abandon(key: u64)

Stop asking, as key. Drops a ready frame that is this key's.

Both halves are needed. Clearing the request alone leaves the last served frame in READY with nobody to take it, and only a take on the same key can remove it. A region is at most 256 KiB, so the leak is smaller than the one capture::abandon fixes, but it is the same leak.

#pub fn take(key: u64) -> Option<Peeked>

Take the latest served frame, if it is key's. Leaves the slot empty.

DESTRUCTIVE, deliberately. A non-destructive read gives the panel no way to tell a fresh frame from the previous one it already printed, and holds the pixels alive after the panel has finished with them.

#pub fn serve(device: &wgpu::Device, queue: &wgpu::Queue)

Run the readback stream. Once a frame, from the render loop.

Three acts, in this order: poll for finished maps, drain what finished, and submit the next copy. The order matters — draining before polling would always be one serve behind, and submitting before draining would find no free slot on the frame a slot became free.

#pub fn view_from_basis( eye: [f32; 3], right: [f32; 3], up: [f32; 3], forward: [f32; 3], ) -> [[f32; 4]; 4]

The view matrix the shader expects, column-major.

Camera space is x RIGHT, y UP and z FORWARD, so a splat in front of the eye has a positive z. The EWA Jacobian divides by that z twice and the quad is placed from the same value, so a convention with z pointing backwards puts every splat on the wrong side of the screen while the ellipses stay the right shape — a picture that looks plausible and is mirrored.

The three axes must be orthonormal. This builds the inverse of a rigid transform by transposing the rotation, which is only the inverse when they are.

#pub const fn band_floats(band: u8) -> usize

How many floats of harmonic one band costs per splat.

#pub fn oct_encode(n: [f32; 3]) -> [f32; 2]

A unit vector as two numbers in -1..1, octahedrally.

The sphere is projected onto an octahedron, which is unfolded into a square. It is a well behaved mapping — no pole, and an error under a thousandth of a degree at this precision — and the reason it is used here is that it FITS: the scale and colour buffers each carry a padding float that vec4 alignment demands and nothing reads.

A normal buffer of its own would be a ninth binding against a limit of eight, and another sixteen bytes a splat against a cap this layout is already shaped around. Two floats that were being written as zero anyway cost nothing at all.

#pub fn sh_degree_fit(count: usize) -> u8

The highest harmonic degree a cloud of count splats can carry.

Each band is its own binding, so the test is on the LARGEST band and not on their sum. Band 3 is 84 bytes per splat, band 2 is 60 and band 1 is 36, so a degree that fits implies every lower one fits.

The answer is the memory lever the panel reports. A cloud whose band 3 does not fit renders at degree 2 with no error anywhere, and a person comparing it against another viewer needs to be told which one they are looking at.

A captured splat already carries the light that fell on it when the photographs were taken. Lighting it again puts a second light on a surface that has one baked in, which is not what the capture looked like and is not physically anything.

It earns its place as an INSPECTION tool. A scan's colour is often flat and evenly exposed, and shape that the eye cannot find in it appears at once under a raking light. So this is off unless somebody turns it on, and the panel says what it is for.
