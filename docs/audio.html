Audio is the audio module of warp_core, re-exported by warp_sdk, which holds everything the sound monitor reads and the one mixer that a game adopts so that the monitor has a signal. The engine plays no sound of its own. It owns the mixer that the game plays through, so that the mix exists somewhere a tool can reach it.[1] The module is native only, and the bus sits behind the audio feature, which warp_sdk enables by default.

Submodule Holds
audio::bus The mixer the game takes sinks from, with a tap on it
audio::scope Rings of samples that the tap fills
audio::events What the game says it started, and which of it is still on
audio::spectrum Samples to one column of a spectrogram
audio::chord Samples to notes, and notes to a chord
audio::library Sound files on disk, found by walking them

Design

audio::bus is the only submodule that names rodio, and rodio is the only part that links a system library. With the feature off, the measuring half survives: rings, spectrogram, chord detector and library. None of these reads a device.[2] BUS_SAMPLE_RATE is 44,100 Hz and BUS_CHANNELS is 2. They are declared in the parent module for that reason.

Music and sound effects stay apart from the bus to the display. Each Lane has one ring and one spectrogram trace. A mix can be summed later, but two lanes cannot be recovered from a mix that was flattened early.

No module holds a list of game sounds. An event carries a name as free text, and the library finds files by walking directories. A new sound appears in the monitor with no edit here. The cost is that a typo becomes a new sound, which the source accepts for a monitor that decides nothing.

What a game does

Two things, and neither changes how it handles a voice.

  1. Build a Bus on the output stream handle, and take sinks from it in place of rodio.
  2. Call events::push where a sound starts.
use warp_sdk::audio::{Bus, Lane};

let (_stream, handle) = rodio::OutputStream::try_default()?;   // hold _stream
let bus = Bus::new(&handle)?;
bus.sink(Lane::Sfx).append(source);                            // rodio source

A game with no sound device can feed the monitor directly:

audio::scope::write(audio::Lane::Sfx, &tone);

A sound left uninstrumented is heard in the spectrogram and missing from the list. The source calls this visible discrepancy the intended failure mode.

reset zeroes the rings and empties the queue. The transport Stop edge calls it, because the host stops a game by no longer calling its hooks, and a rodio sink plays on its own thread regardless.

The bus

Bus sits between the sinks of a game and the rodio output stream. Each sample is summed into a lane, tapped, and handed to the device, so what the monitor draws is what the device gets. Before it, each voice went directly to the output stream, and rodio summed them past the last line of game code. Tapping each voice separately would give signals slid past each other in time, not the mix.[3]

Bus::sink returns an ordinary rodio sink, with the same pause, volume, stop and reaping that rodio gives. Bus::play_raw plays a source directly on a lane.

The tap never ends its stream. A rodio mixer ends the moment that it has no live source, and a mixer drops a source that ends. A lane handed raw to rodio would therefore be dropped at the first silence, permanently and with no error. The tap yields 0.0 instead, which also keeps the lanes sample-aligned.[4]

Scope rings

audio::scope holds one ring of mono samples per lane, of CAPACITY 32,768 samples, which is 0.74 s at 44.1 kHz. A mutex in the audio callback would cause an audible click, because the callback must fill the device buffer before a deadline. So the storage is a flat array of atomics, and each lane has one writer.[5]

scope::write appends a block of samples, so that the cursor publishes once per callback. scope::latest and scope::latest_mixed fill a buffer with the newest samples, zero-padded at the front. scope::take_peak returns the peak and zeroes it. The writer never waits for a reader, so a read can tear only if the draw thread stalls for most of a second.

The rings live in one Block, and scope::adopt points both processes at a shared mapping. See Host link.

Function Purpose
scope::set_format Told once, by the bus, at device open
scope::sample_rate Hz, or 0 before the bus exists
scope::write Audio thread: one block of mono samples
scope::cursor Total samples ever written to a lane
scope::latest The newest samples of one lane
scope::latest_mixed The newest samples of every lane, summed
scope::take_peak Peak magnitude since the last call
scope::reset Zero each lane
scope::adopt Unsafe: use a block that another party holds
scope::release Return to the block of this process

latest_mixed sums by index, which is correct only because the lanes advance together. Each lane is a source that never ends, and all are handed to rodio at once.

Events and voices

SoundEvent is one start, built with SoundEvent::sfx or SoundEvent::music and chained setters for variant, path, duration, gain and spatial attenuation. events::push cannot fail and does not report whether anyone listens, so a game grows no branch around each sound.

The queue holds QUEUE_LIMIT events, 512, and drops its oldest. dropped counts the loss, because a display that silently loses events looks the same as a game that went quiet. VoiceBoard::poll drains at most MAX_DRAIN_PER_FRAME, 256, and tracks live voices.

The game reports starts only, because a voice ends on the rodio thread inside a sink that the game has dropped. A Voice retires when its declared duration elapses, and each derived end is marked as derived. A declared duration of zero means that the estimator gave up, so it is treated as absent: an ordinary voice gets UNKNOWN_VOICE_LIFE, 4 seconds, and an exclusive voice gets HELD_VOICE_LIFE, 30 minutes.[6] An exclusive voice ends when the next voice takes its lane.

VoiceBoard is the panel's view, built with a history capacity. VoiceBoard::live gives the live voices, VoiceBoard::live_on counts one lane, VoiceBoard::history gives finished events, VoiceBoard::seen gives a running count, and VoiceBoard::tally counts by name. A Voice holds its event, its expected end, and end_is_guessed. The panel must show that flag, because a guessed end drawn as a measured one is a claim that the engine cannot support.[7]

Spectrum

Analyzer turns one block of mono samples into one spectrogram column, with a Hann window, a hand-written radix-2 FFT, and a fold onto a log frequency axis. There is no FFT crate. Linear bins are the wrong axis, because they crush what a musician can hear into the bottom eighth of the display. So bands are spaced geometrically from F_LO, 30 Hz, up to Nyquist. FFT_SIZE is 1024, DEFAULT_FLOOR_DB is -90, DEFAULT_CEIL_DB is 0, and DEFAULT_SHARPEN is 0.75. Nothing allocates once the Analyzer exists.[8]

Chord detection

Detector takes mono samples and gives a named Chord. It runs its own transform of WINDOW 16,384 points, because at the spectrogram resolution two adjacent bass notes land in one bin.[9]

Harmonics are subtracted and not ignored. A plucked low E puts as much energy on its third harmonic as on some played notes, so the detector takes the loudest pitch by salience, removes that note's overtone series from the peak list, and repeats. Tuning is measured as a circular mean of each peak's deviation, and subtracted before the fold to twelve pitch classes.

Detector::feed takes one frame. Detector::now is what is sounding, and it flickers because near-ties are real. Detector::dominant is a vote that decays over about four seconds. Inversions are not named: the result is a root and a Quality, so C/E reads as C.

Chord holds a root pitch class, with 0 as C, a Quality, and a score, which is a cosine against the template and not a probability. Chord::name gives a symbol such as Am. Quality::CHORDS lists the eight templates: major, minor, dominant 7, major 7, minor 7, suspended 2, suspended 4 and diminished. Quality also has a single-note fallback, which is not a template.

Library

LibraryState walks a directory of sound files on a worker thread, so the walk never runs on the draw thread. LibraryState::rescan starts a walk, and leaves a matching one running. LibraryState::poll takes a finished Scan and never waits.

The tree is the registry. A Clip has a group that is its directory path from the root, and a category that is the first component. Dropping a directory into the library makes it appear on the next walk. AUDIO_EXTS decides what counts as sound by extension. MAX_CLIPS, 20,000, and MAX_DEPTH, 12, bound a walk of the wrong root, and both report into the errors list of the Scan when they bite.[10]

Scan holds the root, the groups, clip and byte totals, the errors, and the time taken. LibraryState::set_filter and LibraryState::filtered narrow the list.

Across processes

The audio callback runs in the game, and the panel runs in the editor. Samples do not travel on the socket, because two lanes at 44.1 kHz would be 353 KB of floats a second, and more as JSON text. One message carries the name of a shared page, and the callback writes into it. See Host link.

#pub enum Lane

Which of the game's two kinds of sound a block of samples belongs to.

A single mixed lane can be summed out of these two, and two lanes cannot be recovered from one mixed one.

#pub struct Analyzer

Turns a block of mono samples into one spectrogram column.

It holds every buffer the transform needs, sized once, so a column costs a window multiply, a transform per lane and a fold, and no trip to the allocator. A free function taking the scratch by argument was the first shape and made every caller carry six buffers it had no opinion about.

12 methods
#pub fn new(bins: usize) -> Self

bins is the number of output bins (spectrogram rows). Typically 128..256.

Everything is allocated here and nothing after. Zero bins is allowed and yields an analyzer that produces an empty column; rejecting it with a panic was considered and lost, because the caller sizes bins from a panel height that is legitimately zero while a dock animates.

#pub fn multi(bins: usize, windows: &[usize], hop: usize) -> Self

One analyzer reading windows window lengths, emitting a column every hop samples.

windows is a set of powers of two; anything else in it is dropped rather than refused, because the alternative is a panic in a display path over a constant somebody mistyped. An empty set — or one that is empty after the filter — falls back to a single FFT_SIZE lane, which is the behaviour of new.

hop matters only to lanes shorter than it: those are placed as many times as fit, so no part of the interval between two columns escapes being looked at.

#pub fn set_sharpen(&mut self, amount: f32)

How much of the window's own smear is taken off the picture, 0..=1.

Zero is the plain fold. One leaves only the reassigned partials, on a floor of black. The default is most of the way up, because the smear is an artefact of the window and not a property of the sound.

For a caller that holds an analyzer only to ask it where the rows are — bin_hz, bin_window — and never feeds it samples. Calling analyze on a buffer of zeros was the alternative and runs the whole ladder to answer a question about labels.

#pub fn db_range(&self) -> (f32, f32)

#pub fn set_db_range(&mut self, floor_db: f32, ceil_db: f32)

The two are sorted, and a range with no width is opened by a hair, so a slider dragged past its partner cannot divide the normalisation by zero. Rejecting an inverted range was the alternative and it makes the caller carry state it has no reason to.

#pub fn analyze(&mut self, mono: &[f32], sample_rate: u32) -> &[f32]

Constants

The rate every lane runs at, in Hz.

Chosen rather than discovered, for the reason in the header. 44.1 kHz is also the rate the game's own assets are at, so the common case does no resampling before the tap and the monitor sees the file's own samples.

The tap folds these to one mono sample per frame before the scope. A spectrogram of a stereo pair is two spectrograms, and nobody reading this panel is asking a question that needs the second one.

#pub struct Block

Every lane's ring, the format they were captured at, and a header that says so — the whole of what the monitor reads.

WHY THIS IS A STRUCT AND NOT A HANDFUL OF STATICS

It was a handful of statics, and that was correct while the game was linked into the editor: one process, one set of rings, the audio callback writing them and the panel reading them.

The game is now a child process. Its callback fills ITS copy of these statics, in an address space the editor cannot see, and the editor's copy stays at zero for ever — the panel reads a rate of zero, calls itself silent, and draws "waiting for audio" over a game that is playing. Gathering the state into one #[repr(C)] block is what lets a second process map the same bytes and read the sound where it is actually being made.

Nothing about the single-process case changes: with no block adopted the accessors work against a process-local one and behave exactly as before.

#pub fn fft_in_place(re: &mut [f32], im: &mut [f32])

Radix-2 in-place complex FFT. re and im must be the same length and a power of two.

Decimation in time: the input is permuted into bit-reversed order and then combined in log2(n) passes of butterflies. Nothing is scaled on the way out, so a forward transform of n points multiplies amplitude by n and the caller divides. A recursive formulation reads better and was rejected because it allocates a pair of half-length buffers per level, and this runs every frame.

A length that is not a power of two, or halves of unequal length, leave the buffers untouched rather than panicking; the display can survive a blank column and a panic in the UI thread takes the editor with it.

#pub fn hann(n: usize) -> Vec<f32>

A Hann window of n points, cached by the caller.

The periodic form, 0.5 - 0.5*cos(2*pi*i/n), whose coherent gain is exactly one half. The symmetric form with n - 1 in the denominator is the right one for filter design and the wrong one here, because it is not periodic in the block it is applied to and leaks a little at the seam.
