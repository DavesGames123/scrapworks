Front end

Article

From Warp Wiki, the reference for the Warp engine SDK

Title and pause menus, save slots, and the settings model and page

Front end
CategoryFront end
Modulewarp_sdk::front
Sourcewarp_sdk/src/front/mod.rs
Examplecargo run -p warp_sdk --example front
cargo run -p warp_sdk --example settings

The front end is the family of kits that a game uses for its title screen, pause menu, end screen, save slots and settings. It lives in the warp_sdk::front module, which holds three submodules and nothing else: front::menu, front::save and front::settings. Each submodule has one owner, and a game uses the full path.[1] The family supplies parts that a game composes, and the game keeps its own screen state.

Parts

Main articles: Menu screens, Save slots, Settings
Kit Holds Writes to disk
Menu screens Title, Pause, End, the shared Button and five layouts Nothing
Save slots Slots, numbered save files with metadata, and the Fields payload helper saves/slot-<k>.save
Settings Settings, a typed model of six groups, and Page, a page with six tabs settings.cfg

Save files and the settings file share one root, under the per-user application data folder, at games/<game>/.

How the parts meet

The worked example front shows the pattern. The screens are one enum in the game. gui asks the menu of the current screen for a MenuAction and moves to the next screen, and render steps the world only in play, so a menu freezes the game.[2]

fn frame(&mut self, ctx: &egui::Context) {
    let action = match self.screen {
        Screen::Title => self.title.show(ctx),
        Screen::Paused => self.pause.show(ctx),
        Screen::End => self.end.show(ctx),
        Screen::Play => {
            if ctx.input_mut(|i| i.consume_key(egui::Modifiers::NONE, egui::Key::Escape)) {
                self.pause.reset_focus();
                self.screen = Screen::Paused;
            }
            None
        }
    };
    if let Some(a) = action {
        self.act(a);
    }
}

A menu returns an action and does nothing else, so each action is the game's to carry out.

Action Usual result
MenuAction::NewGame, MenuAction::TryAgain Start a run
MenuAction::Continue, MenuAction::Load Read a slot through Save slots
MenuAction::Save Write a slot
MenuAction::Settings Show the Settings page
MenuAction::Resume Return to play
MenuAction::QuitToTitle, MenuAction::Title Show the title
MenuAction::Quit End the process

The kits connect at two points. Title::has_save comes from Slots::latest, so Continue shows only when a slot holds a save. The title menu and the pause menu embed the same settings page, so a game writes the settings screen once.[3]

Relation to the shell

Game shell also provides a title, a pause menu and settings, as one wrapper with a fixed look. The two do not share code. front is for a game that owns its screens and its look: it adds save slots, an end screen, five layouts and six tabs of settings. The starter uses front, and it runs each screen change through Cine.

History

The menu and save kits were added on 2026-10-29, in one commit whose subject records the rule of the title screen: a title that always leads in. The settings page followed the same day.
