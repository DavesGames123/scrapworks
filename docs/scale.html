the design-unit scale, the zoom keys and px()

Interface scale
CategoryEngine
Modulewarp_sdk::scale
Sourcewarp_core/src/ui/theme/mod.rs
Public items9

Interface scale is the factor by which SCRAP enlarges every interface measurement and font. The scale module of warp_sdk exposes nine items from the theme code of warp_core, and it is the one part of that theme code that a game receives. The scale is the fix for a problem that every game has, and the palette beside it stays behind.[1]

Why a game needs it

The engine locks egui to one point per physical pixel, on all platforms and displays. This lock is load-bearing, because pointer arithmetic, the camera and the CRT correction all count in physical pixels.[2]

So a retina panel draws a 14 point label at 14 physical pixels, which is half the requested size. An interface written at the default egui sizes looks too small, and no display setting corrects that. Setting pixels per point on the egui context does not help either, because the engine writes that value every frame from three places.[3]

Since the engine cannot give the lock up, the interface grows. Each measurement is a design unit, and px turns it into a pixel count.

Default behaviour

A game normally writes nothing. Renderer::auto_style is true by default. Once per frame, before gui, the engine then runs the zoom keys and installs the Style at the resulting scale. So a game with no styling code answers Command with +, - and 0 and draws at editor sizes.[4]

A game that returns false from Renderer::auto_style styles itself and calls the two functions directly. A host that runs its own zoom keys, such as the Game shell, returns false so that one press does not step the scale twice.

warp_sdk::scale::zoom_keys(ctx, None);   // Command with +, - and 0
warp_sdk::scale::apply(ctx);             // the Style, at that scale

apply installs the Style on a context once per frame, before drawing.

Values

Constant Value
DEFAULT_UI_SCALE 2.0
MIN_UI_SCALE 1.0
MAX_UI_SCALE 4.0

The default of 2 matches a retina display, where the lock costs the most. set_ui_scale clamps to the range.

The three terms

px multiplies a design unit by ui_scale and rounds to a whole pixel.[5] A game calls px in place of a literal for anything that it measures itself, such as a window width. A literal holds one pixel count at each zoom step while the text beside it grows.

scale::px(12.0)

Three terms make up the scale:

  1. The stored setting, which set_ui_scale writes and the zoom keys step.
  2. The window factor, measured per window. The source gives two failures that this corrects: a window on a 1x monitor drew at twice its size, and a torn-off window drew a third larger than the window it came from.[6] A retina window reports 1, so nothing moves on such a panel.
  3. The panel factor, a per-panel zoom in the editor. Panel zoom ranges from 0.4 to 2.5 against the chrome.

chrome_scale is the first two terms. ui_scale is chrome_scale times the panel factor, and it equals chrome_scale outside a panel body. The two factors are thread-locals, because px is reached from several hundred sites through constants, and a parameter would need the same change at each.

Zoom keys

zoom_keys reads Command with +, - and 0. Command is the egui command modifier, which is Cmd on macOS and Ctrl elsewhere. One press scales by 1.25, a share and not a fixed step, so the keys still respond at 400 percent. The keys step the stored scale and not chrome_scale, because on a window that blits, the window factor is above the step, and stepping the combined value made the minus key grow the interface.[7]

The panel argument names the panel that receives keys. With a panel, the plain keys zoom that panel and Shift takes the chrome. With no panel, as in a game, the keys apply to the chrome.

The function must run once per frame in each window, because each window owns an egui context and a key press reaches only the focused context.

Limitations

scale does not include the panel zoom functions, window_scope or panel_scope, which stay in the theme code of the engine. The palette of the editor chrome is deliberately not exported. For game colours, see Palette roles, and for finished controls, see Panel widgets.

Reference

This section lists every public item, as the source defines it.

warp_sdk::scale

Functions

#pub fn apply(ctx: &egui::Context)

Install the palette on a context. Call once per frame, before drawing.

Outside every panel scope, so the chrome — menu bar, transport, tab strips — is built at the chrome scale whatever any panel is zoomed to.

#pub fn chrome_scale() -> f32

The scale of the chrome: menu bars, tab strips, dividers, and every panel that has not been zoomed on its own.

The person's setting, times the factor of the window being drawn. See window_factor for what the second term corrects and why one number cannot serve two monitors.

#pub fn px(v: f32) -> f32

Turn a design unit into a pixel count.

#pub fn set_ui_scale(v: f32)
#pub fn ui_scale() -> f32

The scale in force right now: the chrome's, times the factor of whatever panel is being drawn.

This is what px() reads, and outside a panel body it is chrome_scale.

#pub fn zoom_keys(ctx: &egui::Context, panel: Option<&str>)

Read Command plus +, - and 0, and set a scale from them.

Call this once per frame PER WINDOW, before that window's panels. Per window and not once per process: each window owns an egui context, and a key press only ever reaches the context of the window that has focus. A call made in the primary window alone is a key that does nothing in every torn-off one, which is exactly what it used to do.

The game does not call it: a zoom key inside a running game would resize the HUD and nothing else, and the game has its own key map.

WHICH THING GROWS

panel is the panel the window would send a keystroke to — see DockState::zoom_target. It gets the plain keys, so Command and - inside a terminal shrinks that terminal and leaves the window around it alone. Shift takes the chrome instead, process-wide, which is what the key used to do for everything.

Command is command in egui, which is Cmd on macOS and Ctrl elsewhere, so the keys are the ones the platform browser already uses.

Constants

#pub const DEFAULT_UI_SCALE: f32 = 2.0

Scale used until somebody sets one. Two matches a retina display, which is what the lock costs the most.

#pub const MAX_UI_SCALE: f32 = 4.0
#pub const MIN_UI_SCALE: f32 = 1.0

Smallest and largest scale a person may pick.
