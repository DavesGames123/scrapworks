the rows a game publishes for the Hierarchy and Inspector panels

The census is the channel through which a running application tells the Hierarchy and Inspector panels what exists. The census module of warp_core, re-exported by warp_sdk, carries rows from the application to the panel, and clicks and edits back. A hierarchy panel needs a list of what is alive and a way to say "that one" to its owner, and the engine can supply neither. Each row is a string, an id and a flag word, so the engine never learns what a planet is.[1]

Design

The census is a channel, and the truth lives in the application. The Scene module looks similar and is the opposite: it owns its objects. A hosted game keeps publishing a census of its own world.

The panel asks for what it draws

The source gives the scale that shaped the channel: the selectables cache of Stella Nova has about forty-two thousand rows, and publishing these every frame would be a hundred thousand string allocations a second for a panel with room for forty lines.[2]

The flow is therefore inverted. census_wanted says whether anyone is looking, and is_expanded says which nodes are open. A publisher sends full rows for open nodes and a count for closed ones, so a closed tree costs one row per category. Nothing enforces this. A publisher that ignores the expanded set is correct and slow.

want_census is what the panel calls on each frame that it draws. The claim expires after WANT_GRACE publishes, which is 3, not 1, because the panel and the publisher run in an order that neither controls.

Usage

Publish once per frame, gated on interest.

if census::census_wanted() {
    let w = &self.world;
    let mut row = census::Entity::new(1, 0, "Drifter");
    row.params = vec![
        census::Param::new("x", census::Value::Float(w.pos.x)),
        census::Param::new("y", census::Value::Float(w.pos.y)),
        census::Param::new("energy", census::Value::Float(w.energy)),
    ];
    census::publish(census::Census {
        kinds: vec![census::Kind::new("Drifter", [226, 159, 62], census::Focus::World)],
        rows: vec![row],
        ..Default::default()
    });
}

census::publish overwrites the generation of the snapshot and returns the new value, because the publisher must file its key table under that number.

Rows

Census holds kinds, rows, a generation and a note. A publisher that caps a category says so in note, because a silent cap reads as "that is all there is".

Kind is one category, named once: a plural name, a color for the dot, and a Focus. Focus decides what the panel draws, a crosshair for a world row or a frame for a screen row. The engine does not act on it.

Entity is one row.

Field Meaning
id The publisher's EntityId
kind Index into the kinds list; out of range draws unstyled
parent ROOT for a top-level row
name The label
detail The short right-hand column
flags SELECTED, HIDDEN, FOCUSABLE, EXPANDABLE
children How many children exist, whether sent or not
params Editable values, filled only for open rows

ROOT is 0, so a publisher that hands out indices starts at 1. A row with a parent that is not in rows draws at the top level and is not dropped. Rows may arrive in any order. HIDDEN rows draw dimmed, because "it is there and it is off" is what a person opens a hierarchy to learn. EXPANDABLE applies even when no child rows were sent.

Generations

Ids belong to the publisher, and the useful ones are indices into a table that it rebuilds on each publish. An index means something only against the table that produced it, and a click always arrives at least one frame after that table. So each Request carries the generation that it was drawn from. The publisher keeps its last few tables, resolves against the one named, and refuses what has aged out.[3]

Without this, a click lands on whatever now occupies that index, and the camera flies to the wrong thing.

Going back

Request is a click, with an Action of Select, Focus, Extend or Toggle. The panel calls request, and the publisher calls drain_requests. The queue holds REQUEST_LIMIT entries, 64, and drops the oldest, which keeps the most recent intent.

Edit is a changed value. set_param and drain_edits are its queue, separate from requests because Value can hold a string. Edits coalesce on the row and parameter index, where requests do not. A slider held for a second gives sixty values and only the last is wanted, but a click pressed twice is two clicks.[4] EDIT_LIMIT is 256 distinct parameters.

set_highlight and highlight carry hover, so that a game can draw its own highlight. set_reveal runs the other way: the publisher names what just became selected, and the panel scrolls to it once. It is a one-shot and not a state, because a level that kept asserting would fight the mouse wheel. inspect, inspecting, set_inspect and take_inspect_reveal manage which row the Inspector shows.

Values

Param is one named value on a row, with name, value, range, unit, readonly and group. Value is deliberately short: Bool, Int, Float, Color, Text and Vec2. Each variant has one obvious control. A value that fits none is sent as Text, and the publisher owns the parse. A publisher checks Value::same_type before it applies an edit, because an edit of another type means that the two sides disagree about a parameter.

A range of none draws a drag field with no stops. readonly draws a greyed value that the publisher computes. group is a free heading string such as "Transform", because the engine does not know the categories of an application. Textures are not a variant. A publisher sends a path as Text, and the panel decides that it is a picture.

Params count as nothing in the children field, and they are filled only for open rows, so a closed tree costs the same as before they existed.

Across processes

install takes a snapshot published in another process and keeps its generation. Renumbering on arrival would send back a generation that the publisher never issued, and each click would be refused. install refuses a generation of 0 and a generation that goes backwards, so a restarted transport cannot resolve ids against a world that is gone. reset_generation is the separate call for a forwarder when a world ends. clear drops the snapshot and leaves the counter alone, so that a local publisher never reissues a number.[5]

Host link does the forwarding in pump_census.

with_census reads the snapshot through a closure, because cloning forty thousand strings to draw forty is the cost this design avoids.

COALESCES on (id, param). A slider dragged for a second is sixty calls naming one parameter, and every one of them but the last describes a value the person has already moved past. Queuing them makes the publisher apply a recording of the drag, one frame per frame, and the knob keeps moving after the mouse has stopped.

The id is enough to key on WITHOUT the generation, and it has to be: an edit made against generation 12 and a correction made against 13 are the same knob, and keeping both would apply the older one second.

#pub fn inspecting() -> Option<EntityId>

#pub fn set_inspect(id: EntityId)

Publisher: the subject is now THIS row. ROOT for "it is gone".

AN ID IS NOT A HANDLE, AND THIS IS WHERE THAT BITES. A publisher whose ids are indices into a table it rebuilds — which is the arrangement this channel was designed around — hands out an id that names a different thing on the next publish. A request survives that because it carries the generation it was drawn from and is resolved once, immediately. The Inspector's subject cannot: it is a LEVEL, read every frame, for as long as somebody leaves the panel open.

So the publisher owes it a correction. Every publish, resolve the id the panel is holding against the table it came from, find that same thing in the table being sent, and say so here. The subject then follows the OBJECT while the numbering moves under it, which is the same guarantee set_expanded asks for and gets for expandable rows.

A publisher whose ids are already stable never has to call this.

It does not scroll and does not open a panel — the only thing it changes is what the Inspector is about. set_reveal is the one that moves a list.

#pub fn take_inspect_reveal() -> Option<EntityId>

Host: a click asked for the Inspector. Consumed, so the pane opens once.

A one-shot for take_reveal's reason and one more: the host answers it by splitting the layout, and a flag that stayed set would re-split every frame.

#pub fn want_census(on: bool)

Panel: I am drawing this. Call it on every frame the panel draws.

false gives up immediately, for a host that knows the panel has gone. Not calling it at all gives up within WANT_GRACE publishes, which is the path that actually carries the weight — see the static above.

A panel torn off into another window still writes this: the census is process memory, so the panel works anywhere in this process.

#pub fn census_wanted() -> bool

Publisher: is it worth building a census at all.

One relaxed load per frame when the answer is no, which is the common case and the one that had to be free.

#pub fn set_expanded(ids: impl IntoIterator<Item = EntityId>)

Panel: replace the open set.

THE PUBLISHER'S SIDE OF THIS IS A CONTRACT, and it is easy to break by accident. The ids of EXPANDABLE rows must be stable from publish to publish, or the set the panel hands back names different rows every time and the tree opens and shuts on its own.

It is easy to break because the obvious implementation — mint an id per row as the rows are built — makes a heading's id depend on how many rows came before it, and therefore on which OTHER headings are open. Opening Planets then renumbers Stations, and Stations collapses.

A publisher that reserves a fixed slot per heading, filled whether or not that heading appears, has no such coupling. Rows that are not expandable may be numbered however is convenient — a click carries its generation, so those only have to be stable within one publish.

What arrives is the EFFECTIVE open set and not the clicked one. The panel's tree is open until a person shuts it, so almost every id in here got there without a click; a publisher told only about the clicks would send no children for the whole of a tree the panel is drawing wide open.

#pub fn is_expanded(id: EntityId) -> bool

Publisher: should this node's children and values be sent.

THE INSPECTED ROW IS ALWAYS OPEN, whatever the tree says. Its values are the whole content of a panel that can be the only one on screen — the tree may be behind another tab, in another window, or shut — and a publisher that filled params for the tree's open set alone would leave that panel permanently empty for the case it exists to serve.

One extra relaxed load per call, against a lock this already takes.

#pub fn expanded() -> HashSet<EntityId>

Publisher: the whole open set, for a builder that would otherwise take the lock once per candidate node.

Carries the inspected row for the reason is_expanded does, so the two cannot disagree — a publisher that switched from one to the other would otherwise silently stop filling the panel.

It aims the Inspector too, and does NOT raise it. Those are deliberately different: a person who clicked a planet in the game window wants the panel they already have to be about that planet, and does not want a pane appearing over what they are looking at. Only a click in the tree opens one.

#pub fn take_reveal() -> Option<EntityId>

Panel: a row to scroll to, consumed. See the banner for why it is a one-shot: the panel owns its scroll once it has honoured this.

#pub fn publish(mut c: Census) -> u64

Publisher: install a new snapshot.

The generation field of c is overwritten with the next value, so a publisher does not track it. The value it gets is returned, because the publisher's key table has to be filed under exactly that number.

#pub fn generation() -> u64

The generation of the snapshot now installed, without taking the lock.

#pub fn install(c: Census) -> bool

Forwarder: install a snapshot that was published somewhere ELSE, keeping the generation the publisher minted.

The difference from publish is the whole reason this exists. publish overwrites the generation because the publisher and the reader share this counter — one process, one sequence. When the publisher is a game in another process, they do NOT: the game's key table is filed under the game's number, and a request the panel draws from this snapshot has to name that number for the game to resolve it. Renumbering on arrival would send back a generation the publisher has never issued, and every click would be refused as aged out.

So the wire is the authority and this end follows it. GENERATION is set rather than incremented, which is also what keeps census_wanted working on this side: the panel's claim expires against a counter that only moves when a census actually arrives, so a game that stops publishing lets the interest go stale exactly as a local publisher would.

Going BACKWARDS is refused. Sockets deliver in order, but a transport that restarts gives the next game a generation of one while the panel is holding rows from the last one's thousandth, and installing that would make every id in flight resolve against a table from a world that is gone. A caller that means "new world" calls clear first, which resets nothing here — see the note there — so the guard is on the number and not on the caller.

Returns whether the snapshot was taken.

#pub fn reset_generation()

Forwarder: forget the generation, for a world that has ended.

clear empties the snapshot but deliberately leaves the counter where it is, because a local publisher's next publish must not reissue a number a request in flight was drawn from. A forwarder has the opposite problem: the next world is a different process that starts its own sequence at one, and install refuses anything below what the last one reached.

Separate from clear so the ordinary path cannot reach it by accident. Calling this while a local publisher is running would let it mint a generation twice.

#pub fn with_census<R>(f: impl FnOnce(&Census) -> R) -> Option<R>

Panel: read the snapshot.

A closure rather than a clone, because the panel reads it once per frame and cloning forty thousand Strings to draw forty of them is the cost this whole file is arranged to avoid.

#pub fn clear()

Drop the snapshot and reset the ask.

For a transport that goes back to Stopped: the world is gone, and a panel still listing its planets would be reporting a world that no longer exists.

#pub const EDIT_LIMIT: usize = 256

Higher than the request limit and it barely matters, because coalescing means the queue grows with the number of parameters touched and not with the length of the drag. A person cannot have two hundred and fifty six knobs in flight; a publisher that has stopped draining can.

#pub const WANT_GRACE: u64 = 3

How many publishes a single assertion of interest survives.

Three, not one: the panel and the publisher run on the same thread but in an order neither controls, so a claim made after this frame's publish must still be alive at the next one.
