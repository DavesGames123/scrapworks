Custom windows
CategoryEditor channels
Modulewarp_sdk::window
Sourcewarp_core/src/window/mod.rs
Public items26

Custom windows are panels that an application adds to the Warp editor without editing the editor. The window module of warp_core, re-exported by warp_sdk, holds the facts of a window as one struct and one trait, and keeps a process-wide table of them. An author implements WarpWindow, with its two methods spec and ui, calls register before run, and gets a tab, a row in the View menu, a place in the layout, and a tear-off to a real OS window.[1]

Usage

use warp_sdk::window::{Group, WarpWindow, WindowSpec};

#[derive(Default)]
pub struct MeterWindow {
    samples: u32,
}

impl WarpWindow for MeterWindow {
    fn spec(&self) -> WindowSpec {
        WindowSpec::new("meter", "Meter")
            .group(Group::Debug)
            .summary("What the frame cost, as a number.")
    }

    fn ui(&mut self, ui: &mut warp_sdk::egui::Ui) {
        ui.label(format!("{} samples", self.samples));
    }
}

Register it from main, before run:

warp_sdk::window::register(Box::new(MeterWindow::default())).ok();   // once, before run

WarpWindow::spec is read each frame, so a title can carry live state. WarpWindow::on_close is an optional third method for a window that holds something to release.

The spec

WindowSpec::new takes a bare name and a title. The id gets the KIND_PREFIX, window., added once, whether or not the caller wrote it.

Builder Effect
WindowSpec::group Which View menu group it is filed under
WindowSpec::pinned It cannot be closed
WindowSpec::primary_only It cannot leave the primary window
WindowSpec::standalone It may become its own process
WindowSpec::undocked Kept out of a reset layout; the View menu still has it
WindowSpec::source The file that the Windows panel shows beside it
WindowSpec::summary One line about its purpose

The defaults are closable, tearable, docked and not standalone. Group has Scene, Assets, Code, Debug and Tools, and Tools is the default. The engine names no menu: these are coarse kinds that an editor maps to its groups.

Design

The dock was always open. It holds a panel id, which is a string, and asks a host for everything else. The closed part was the host: one panel's facts were written at fourteen match sites in the editor, and each site ended in a default arm. A forgotten site returned the wrong answer and still compiled.[2] A WindowSpec answers all fourteen from one value, so a registered window is complete or absent, with no state between.

window is published and dock is not, and that is one decision. An author wants to say what a panel is called and to draw it. dock is the same want with a tree of rects, a drag protocol and a tear-off across processes attached.[3]

The table is global, like the other things that an application declares, such as the atlas set in Image atlases and the scene layers in Render passes. The engine must not name the application, so the application hands its declarations in. A window must be sendable between threads, because the table is a static reachable from any thread. Nothing draws off the main thread.

Registration

register returns a result. It fails for an empty name, and for a name with a :, which the dock reads as an instance separator. So the full kind is window.hello, never window:hello.

A second window of a name already registered replaces the first and returns an error. Two windows of one id would give the dock a panel that it could show twice and close once, and silently keeping the first is the failure that takes longest to see.[4]

The host uses owns, specs, spec_of, count, draw and close_all. owns tests the prefix and nothing else, so a host holds no list of ids.

draw holds the lock for the body of one window, and it uses try_lock. A window that drew itself from inside itself would deadlock, so it gets a line of text saying which window did it.[5]

register_disable and disable hold a closure per panel kind that releases reopenable GPU resources, because freeing a tool's texture id needs the egui renderer. A tool that owns a target need not be a WarpWindow. A second disabler replaces the first and returns an error, the same contract as register.

What it is not

It is not dynamic loading. There is no libloading, dlopen or wasm host in the workspace. A registered window is code compiled into the binary that runs it, so a rebuild is part of authoring, and there is no reload.[6]

The surface a window may name

A window keeps to the published surface of warp_sdk. A window that keeps to it builds in a crate of its own, and a window that reaches past it cannot leave the repository. Widening what a window may name means one reviewed line of warp_sdk/src/lib.rs.[7]

Windows that ship with the editor sit in warp_editor/src/windows/, one file each. They name warp_core, and a test still holds them to the published surface by reading the allow-list from warp_sdk/src/lib.rs.

The Windows panel of the editor lists registered windows. It shows the source of the selected window beside the window itself, running, as the same registered object that the dock draws. Its API tab draws warp_sdk/API.md. Pressing Create writes a file from a template, and adds the lines that declare it. The panel prints the build command and does not run it, because a binary cannot replace itself while it is the running process.

Limitations

  • A rebuild is part of authoring.
  • There is one window per name.
  • A window must be sendable between threads.
  • The scaffold needs a source tree, so a shipped binary with no warp_editor/src/windows beside it has nowhere to write.

#pub fn close_all()

Tear down every registered window, in registration order.

The host calls this once at shutdown, so a registered tool reaps a port, a child process, or a target the way the built-in panels do. It generalises the editor's hand-written stop list: a tool the shell never names still gets its on_close. A poisoned table is skipped, because a panic on the quit path would strand the very resources this reaps.

#pub fn register_disable( kind: impl Into<String>, f: impl Fn(&mut egui_wgpu::Renderer) + Send + 'static, ) -> Result<(), String>

Register the closure that releases a panel kind's reopenable resources.

A tool calls this once, before run. A second disabler for a kind already registered REPLACES the first and returns Err, the same contract as register, so a double registration is seen and not silent.

#pub fn disable(kind: &str, gui: &mut egui_wgpu::Renderer) -> bool

Release a panel kind's reopenable resources. False when no kind matches.

The dock calls this on per-panel close, with the renderer it holds at close time. A poisoned table is skipped, so a close gesture cannot panic. A disabler must not call back into this registry, because the table stays locked for the call, the same rule close_all keeps for on_close.

#pub fn draw(kind: &str, ui: &mut egui::Ui) -> bool

Draw one window's body. False when no window has that kind.

try_lock and not lock: see the module header. A window that draws itself from inside itself gets a line of text, not a frozen editor.

Where a window asks to be filed in the View menu.

The engine names no menu. These are the coarse kinds an editor can map onto whatever groups it has, and Tools is the answer for a window that does not care — which is most of them, and is what the editor already does with a panel no group arm names.

Everything about this window that is not its body. Read every frame, so a title may carry live state the way the Code panel's does.

#fn ui(&mut self, ui: &mut egui::Ui)

Draw the body. The Ui is already clipped to the panel's rect and already inside the panel frame, so an implementation draws content and nothing else.

#fn on_close(&mut self)

Release what Drop never reaches. The host calls this once when it tears the tool down, so a window that holds a port, a child process, a pipeline, or a render target can reap it. The default does nothing, because most windows own only what Drop already frees.

This is the registered-tool twin of the built-in panel stops the editor runs at quit. A tool reached this way needs no editor code that names it.

Constants

#pub const KIND_PREFIX: &str = "window."

What every registered window's id starts with.

The prefix is the whole of the editor's answer to "is this one of mine". A host tests the prefix and then asks this module, which means the host holds no list of registered ids and cannot fall out of date with one.

It is not INSTANCE_SEP's separator. The dock cuts an id at ':' to find a kind, so a registered window's full kind is window.hello and never window:hello — the second would make every registered window an instance of one kind called window.
